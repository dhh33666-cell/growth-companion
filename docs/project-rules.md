# AI 成长秘书：项目当前说明书

> 最后更新：2026-08-19  
> 用途：记录项目**当前有效**的架构、产品规则、部署状态与操作约定。历史开发过程请查看 `docs/development-log.md`。

## 1. 项目定位

这是一个面向个人长期成长的 RPG 化成长秘书。它帮助用户记录学习、训练、饮食、习惯与每日收获，并将任务完成情况转换为经验、等级和五项成长属性。

核心目标：让学习、健康、生活记录与适度奖励形成可持续的成长系统；AI 教练提供理性、基于已有记录的建议。

## 2. 当前技术与运行环境

- 前端与应用框架：Next.js 15（App Router）+ React + TypeScript
- 样式：Tailwind CSS + 自定义游戏化 UI
- 数据与认证：Supabase（邮箱 Magic Link 登录、Row Level Security）
- 部署：Vercel
- AI：兼容 OpenAI 协议的中转 API；接口失败时降级为本地建议
- 版本管理与代码托管：Git + GitHub

## 3. 数据与安全约定

- 用户必须登录后才能使用 Supabase 云端模式。
- 数据变更会先保存到当前浏览器，再延迟约 0.7 秒自动同步到 Supabase；不需要手动上传。
- 浏览器会保留最近 10 份本地数据快照；设置页提供“尝试恢复本机备份”，用于降低异常同步或误操作造成的数据丢失风险。
- 若出现“本地已保存，云端同步稍后重试”，说明当前变更暂未成功上云，但仍保存在该浏览器本地。
- Supabase RLS 要求用户只能读写自己的数据。
- 不在代码、日志、聊天记录或 GitHub 中写入任何真实密钥。
- `.env.local` 仅保留在本地，不能提交到 GitHub；仓库只保留 `.env.example`。
- 已配置的环境变量名称：
  - `NEXT_PUBLIC_SUPABASE_URL`
  - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
  - `AI_BASE_URL`
  - `AI_API_KEY`
  - `AI_MODEL`

## 5. 当前功能清单

### 5.1 任务与计划

- 新增、编辑、删除任务。
- 任务可标记完成，也可以取消完成。
- 完成/取消完成会相应增加/回退经验与属性。
- 支持学习、AI、英语、训练、习惯、社交、休息等任务分类。
- 支持主任务标记、计划时长、实际时长、日期、备注与优先级信息。

### 5.2 生活记录

- 训练：动作、时长、状态、备注。
- 饮食：餐次、内容、主观健康程度、奖励餐标记。
- 日常：睡眠、作息/饮水、阅读/整理、社交、休息娱乐等。
- 今日记录可删除。

### 5.3 RPG 成长规则

五项属性：

- 智力：学习、分析、英语等。
- 创意：AI 实操、产品构思、输出等。
- 体力：训练和恢复相关行为。
- 耐力：持续训练、专注、规律作息等。
- 自律：计划完成、习惯与连续性。

逾期任务规则：

- 某日未完成的任务，在次日首次进入应用时结算。
- 所有未完成任务都会扣减经验和相关属性。
- 主任务按全额扣减；普通任务按半额扣减。
- 扣分有每日上限，避免单日惩罚过重。
- 将逾期任务延期到未来或直接删除，会退回该任务已扣除的经验与属性。
- 标记逾期任务完成不会补发此前被扣的经验。

### 5.4 奖励

- 具备奖励池和抽取资格机制。
- 云端奖励池为空时，系统会自动恢复四个默认奖励：奶茶、电影、游戏、小食，并自动同步到 Supabase。
- 支持新增、编辑、删除、启用/停用奖励，以及一键恢复默认奖励池；为避免空池，页面至少保留一个奖励。
- 每个奖励可配置名称、Emoji、消费/时间类型、预算金额、冷却天数和每周最多次数。
- 奖励包含奶茶、果茶、小食、电影、游戏、综艺/电视时间、休息等方向。
- 当前抽取页面已展示预算、冷却和每周上限；抽奖筛选是否严格执行这些限制仍应在后续迭代中加强。

### 5.5 AI 教练

- 可在 AI 教练页提问学习拆解、优先级、训练恢复和日程安排等问题。
- AI 不能直接修改任务、奖励、属性或云端数据。
- 不输出医疗诊断、极端节食或危险训练处方。

### 5.6 每日收获

用于记录学习、刷视频时遇到的术语/名词。

- 字段：名词、定义、来源、领域分类、日期。
- 默认分类：数据分析、AI、英语、其他；支持新增与删除自定义分类。
- 支持编辑、删除、关键词搜索、按分类筛选、按日期倒序回顾。
- 暂不使用 AI 自动生成定义。
- 删除自定义分类后，其下条目归入“其他”。

## 6. 已知问题与技术债

### 云端同步重复写入与异常清空（已修复，需发布）

- 原因：旧版同步会删除后重新插入全部数据；多个同步请求同时执行时，任务和每日收获可能出现重复。
- 关联风险：当“每日收获”读取异常被旧版当作空列表处理时，旧版全量删除逻辑可能清空云端收获。
- 修复：同一用户的同步请求改为串行执行；不再先删除整张数据表；任务、生活记录、奖励、记忆使用稳定 ID 的 `upsert`；读取云端时会按内容去重；每日收获读取失败会保留本地数据而不是覆盖为空。
- 已有重复：发布后的首次同步会以去重后的本地数据重写云端数据；若当前浏览器仍显示重复，刷新一次页面即可让去重后的云端数据重新加载。
- 状态：代码已完成验证，待推送 GitHub 并由 Vercel 部署。

### 本地服务

- `localhost` 仅在当前电脑、且 Next.js 服务正在运行时有效。
- 每次生产构建后，旧的 `next start` 进程可能仍读取旧构建文件；需要停止旧进程后重新启动服务。
- 日常使用优先访问线上 Vercel 网站。

## 8. 修改与发布流程

1. 在本地修改并测试：`http://localhost:3000`。
2. 完成后执行：

```powershell
git add .
git commit -m "本次修改说明"
git push
```

3. Vercel 会自动从 GitHub 的 `main` 分支构建并部署。
4. 在 Vercel 中确认部署状态为 `Ready` 后，线上站点即为最新版本。
5. 每完成一项功能、修复或重要决策，都应更新 `docs/development-log.md`；若改变项目当前规则，也同步更新本文件。
